etf_selection: what the code does and how the pieces fit

This page follows the data from raw market bars to a weighted ETF basket. It shows which modules do each job, which settings change the result, and where the code can mislead you.

How to use this

Sections follow the data, not the folder listing. Snippets are copied unchanged from the files named in the headings. Every number in a Sample data box came from this repository's code and data on 2026-08-10. Coloured boxes mark design choices, traps, and weaknesses.

The process in plain English

The project answers one question: from the liquid US-listed exchange-traded funds (ETFs), which thirty should you hold, and in what proportions? It keeps the 500 most traded ETFs, removes funds without a full eight years of history or a sufficient return, and selects a diversified subset using rank correlations between daily returns. It then applies seven standard weighting rules and checks what a buy-and-hold portfolio would have been worth.

return f"""

    GROUP BY ticker, date
    ORDER BY ticker, date
"""
What it does

Input: the 500 tickers from stage 1. Output: data/raw/daily_close_volume_screened_2016_2025.parquet, 1,081,660 rows and four columns, 500 tickers, 2016-01-04 to 2025-12-31, 11.22 MB on disk. Role: the shared offline data file; four of the six code areas use it as their only source.

Why argMax(close, ts) and not "the 16:00 bar"

argMax(close, ts) means "the close value from the row with the largest ts". A minute bar exists only when a trade occurs, so an illiquid ETF may have no bar at the session's final minute. Taking the last existing bar returns the day's last traded price; a fixed timestamp could return nothing.

Trap

exclusive_end_date() turns the inclusive date 2025-12-31 into the exclusive bound 2026-01-01. Without it, ts <= '2025-12-31' becomes ts <= '2025-12-31 00:00:00' and drops the last trading day. Comparing timestamps with bare dates is an off-by-one-day risk.

Why the file is validated after writing

_validate_parquet_magic() checks that the first and last four bytes are both PAR1. Parquet files use that marker at both ends, so a truncated download fails at export time instead of later as a confusing pandas error.

In plain words

Turn the price list into a date-by-ticker grid, drop tickers with too many missing days, and convert prices into day-to-day returns.

The formula

$$r_{i,t}=\ln\!\left(\frac{P_{i,t}}{P_{i,t-1}}\right),\qquad \text{coverage}_i=\frac{\#\{t: P_{i,t}\ \text{observed}\}}{T}$$

$P_{i,t}$ is ETF $i$'s closing price on sampled date $t$; $r_{i,t}$ is its log return, the natural logarithm of the price ratio; $T$ is the number of sampled dates. A ticker is kept when $\text{coverage}_i \ge 0.80$.

Why log returns rather than percentage changes

Log returns add across time, so the eight-year return is the sum of the daily values. The code uses this for the total-return hurdle, average yearly return, wealth path, and drawdown. Convert the sum back to a percentage with $e^{\sum_t r_t}-1$.

05Stage 3 — the survivor filters

apply_shared_selection_filters() — four hurdles in a fixed order

The filters run in this order. Each one checks that the anchor tickers remain:

  1. Manual blacklist — named exclusions. Raises if an anchor is listed.
  2. Total-return hurdle — cumulative log return must reach MIN_SELECTION_TOTAL_RETURN.
  3. Average calendar-year hurdle — optional; used only when the caller supplies a number.
  4. Volatility band — annualised volatility must fall between MIN_ANN_VOL and MAX_ANN_VOL. Anchors are restored even when they fail.
The formula

$$R_i=\sum_{t=1}^{T} r_{i,t}\;\ge\;\theta,\qquad \bar{A}_i=\frac{1}{Y}\sum_{y=1}^{Y}\ \sum_{t\in y} r_{i,t}\;\ge\;\alpha,\qquad \sigma_i=\mathrm{sd}(r_{i,\cdot})\sqrt{k}\in[\sigma_{\min},\sigma_{\max}]$$

$R_i$ is ETF $i$'s cumulative log return over the whole window and $\theta$ is MIN_SELECTION_TOTAL_RETURN $=0.1823$. $Y$ is the number of calendar years in the sample and $\bar{A}_i$ is the average of the yearly log-return sums, compared against the hurdle $\alpha$. $\mathrm{sd}$ is the sample standard deviation with one degree of freedom removed, $k$ is the number of return periods per year (252 for daily, 52 for weekly), and $[\sigma_{\min},\sigma_{\max}]=[0.10,0.60]$.

Why a volatility band and not a name blacklist

The data does not label leveraged or inverse ETFs. A 60 % volatility ceiling catches many of them, while a 10 % floor removes money-market substitutes whose returns could create an artificially high Sharpe ratio. The band stays useful when new products appear.

The weakness, stated honestly

The total-return hurdle keeps ETFs that rose during the same window used for scoring and backtesting. This is in-sample selection: on 2018-01-01, none of this was known. Do not read the section 10 backtest numbers as expected future performance.

06Stage 4 — correlation and distance

compute_spearman_corr()

filled = log_ret.fillna(log_ret.median())

What it does

Input: the 2,011 by 233 return panel. Output: a symmetric 233 by 233 matrix of Spearman rank correlations. Role: input for every selector and for hierarchical risk parity (HRP).

Why rank correlation rather than ordinary correlation

Spearman correlation is Pearson correlation applied to the ranks of observations instead of raw values. Daily ETF returns can have extreme values, so one crash day can dominate ordinary correlation. Ranks limit that day's influence and can capture consistent relationships that are not straight lines.

compute_distance_matrix() — the signed distance

The formula

$$D_{ij}=\sqrt{\tfrac{1}{2}\left(1-r_{ij}\right)}$$

$r_{ij}$ is the Spearman correlation between ETFs $i$ and $j$; $D_{ij}$ is the distance between them. If $a$ and $b$ are unit-length vectors with $a\cdot b=r$, then $\|a-b\|^{2}=a\cdot a-2a\cdot b+b\cdot b=2(1-r)$, so $\|a-b\|=\sqrt{2(1-r)}$ and dividing by $\sqrt{2}$ scales the result onto $[0,1]$.

Why signed and not absolute distance

The alternative $D = 1-|r|$ would put a bond fund with $r=-0.8$ only 0.2 away from equities, as if it were nearly the same asset. That misses the point of diversification: a negatively correlated holding can offset equities, so the signed formula places it at the far end.

select_by_greedy() — furthest-first traversal

min_dist_masked = min_dist.copy()
min_dist_masked[selected_idx] = -np.inf
best_val = min_dist_masked.max()
...
selected_idx.append(next_idx)
# For each remaining candidate c, min_dist[c] may decrease now that
#   new_min_dist[c] = min(min_dist[c], D[c, next_idx])
min_dist = np.minimum(min_dist, D[:, next_idx])
The formula

$$\text{next}=\arg\max_{c\notin S}\ \min_{s\in S} D(c,s)$$

$S$ is the selected set, $c$ is an unselected candidate, and $D$ is the signed distance matrix. For each candidate, find its nearest selected holding. Choose the candidate whose nearest holding is furthest away.

Why the running min_dist vector matters

Recomputing $\min_{s\in S} D(c,s)$ from scratch would cost $O(n \cdot |S|)$ at each step. Adding a name can only reduce a candidate's nearest-holding distance, so one elementwise minimum with the new column is enough. Each step costs $O(n)$. The source calls this "the key efficiency trick".

select_by_maxdiv() — greedy on a portfolio-level objective

The formula

$$DR(w)=\frac{w^{\top}\sigma}{\sqrt{w^{\top}\Sigma w}},\qquad DR_{\text{EW}}=\frac{\frac{1}{N}\sum_{i=1}^{N}\sigma_i}{\sqrt{\frac{1}{N^{2}}\mathbf{1}^{\top}\Sigma\mathbf{1}}}$$

$w$ is the weight vector, $\sigma$ the vector of individual volatilities with $\sigma_i=\sqrt{\Sigma_{ii}}$, and $\Sigma$ the covariance matrix of the daily log returns. $N$ is the number of holdings and $\mathbf{1}$ a vector of ones, so $w=\mathbf{1}/N$ is equal weighting. $DR=1$ means no diversification benefit at all; higher is better. The measure is from Choueifaty and Coignard (2008).

In plain words

At each step, it adds each candidate in turn, splits the money evenly, and measures the portfolio's risk against the average risk of its holdings. It chooses the candidate with the highest diversification ratio.

Why the covariance is not annualised here

Both parts of the diversification ratio scale with $\sqrt{k}$, so annualisation cancels. The code therefore does not multiply by an annualisation factor.

select_by_kmedoids() — clustering with two seats reserved

The formula

$$\text{medoid}(C)=\arg\min_{j\in C}\ \sum_{i\in C} D(i,j),\qquad \text{assign}(i)=\arg\min_{m\in M} D(i,m)$$

$C$ is one cluster, $M$ is the current set of medoids, and $D$ is the same signed distance matrix. A medoid is an actual ETF in the data, not an average of several ETFs.

What it does

09Stage 7 — turning a basket into weights

src/portfolio_allocation/ contains seven rules, registered in STRATEGY_FUNCTIONS. Six use the same optimisation setup with different objectives; hierarchical risk parity (HRP) is structurally different.

RuleNeedsObjective (annualised where relevant)Character
min_variance$\Sigma$$\min\ w^{\top}\Sigma w$Ignores returns entirely; piles into the calmest holdings
mean_variance$\mu,\Sigma$$\max\ w^{\top}\mu_{\text{ann}}-\tfrac{\lambda}{2}w^{\top}\Sigma_{\text{ann}}w$Classic Markowitz; $\lambda$ defaults to 3.0

Why one shell and seven objectives

Five rules solve the same long-only, fully invested, capped problem with different objectives. Keeping the bounds, sum-to-one constraint, starting point, and convergence warning in one place keeps the rules consistent. min_cvar needs an extra variable, and hrp does not use this optimiser.

Trap

warn_if_not_converged only prints. A failed optimisation still returns result.x, the solver's last attempt. The caller gets no error unless someone notices the console warning, which can scroll past in a notebook.

min_cvar() — the one with an extra variable

The formula

$$\min_{w,\zeta}\ \ \zeta+\frac{1}{T(1-\alpha)}\sum_{t=1}^{T}\max\!\left(-r_t^{\top}w-\zeta,\ 0\right)$$

$r_t$ is the vector of asset log returns on day $t$, so $-r_t^{\top}w$ is that day's portfolio loss. $T$ is the number of days, $\alpha=0.95$, and $\zeta$ is free. Rockafellar and Uryasev (2000) showed that minimising this expression over $w$ and $\zeta$ gives minimum conditional value-at-risk, with $\zeta$ equal to value-at-risk at the optimum. Only losses above $\zeta$ contribute, so the analytic gradient uses losses > zeta.

The formula

$$n_i=\frac{C_0 w_i}{P_{i,0}},\qquad V_t=\sum_i n_i P_{i,t},\qquad r^{p}_t=\ln\!\left(\frac{V_t}{V_{t-1}}\right),\qquad \text{Calmar}=\frac{\mu^{\text{ann}}_p}{\text{MDD}_p}$$

$C_0$ is initial capital; $w_i$ is holding $i$'s target weight; $P_{i,0}$ is its price on the aligned entry date; and $n_i$ is the fixed number of shares bought. $V_t$ is portfolio value on day $t$, $r^p_t$ its log return, $\mu^{\text{ann}}_p$ its annualised log return, and $\text{MDD}_p$ the maximum drawdown. The Calmar ratio is return per unit of worst-case loss.

Why fixed shares rather than fixed weights

Buy-and-hold means buying once and doing nothing. Weighting asset returns each day would silently rebalance to target weights, which is a different strategy and often looks better because it sells winners. The code buys fixed share counts on day one and revalues them each day, so the weights drift as they would in a real account.

The point-in-time rule, and the maths behind it

Why a session column cannot simply be joined onto a bar

A session row summarises a whole trading day: its close, high, and total volume. Joining it to the day's 10:00 bar would reveal the future. attach_session_primitives() therefore withholds the regular_* summary, postmarket_* block, and four next_regular_* columns: 21 columns in total. It keeps earlier context such as prior_regular_close, prior_regular_range, overnight_gap, and the session open.

The formula

Realized volatility of a session, used as the second label one session ahead:

$$\sigma_d=\operatorname{sd}\left(\left\{\ln\frac{p_{i}}{p_{i-1}}\ :\ i\in d\right\}\right), \qquad y^{\text{vol}}_{t}=\sigma_{d(t)+1}$$

The forward return label, attached to every bar of session $d$:

$$y^{\text{ret}}_{t}=\frac{C_{d(t)+1}}{p_t}-1$$

$p_i$ is the close of minute bar $i$; $d$ is one regular session and $i\in d$ runs over its 390 minute bars; $\operatorname{sd}$ is sample standard deviation; $\sigma_d$ is that session's realized volatility; $d(t)$ is the session containing bar $t$; and $d(t)+1$ is the next session with regular bars, not simply the next row. $C_d$ is session $d$'s regular close; $p_t$ is the labelled bar's close. Both labels use only later information.

17Honest limitations

The selection is in-sample

ETFs pass a cumulative-return hurdle over 2018-2025, then are scored and backtested over the same window. Every number in section 10 is fitted to that sample, not a forecast. The repository does not split the sample or run a walk-forward test.

Survivorship bias in the universe

The candidate list contains symbols that traded during 2020-2025 and existed by 2018. ETFs that closed during the window never enter the file. The universe is therefore "funds that made it", not "funds you could have chosen in 2018".

No costs, no taxes, no execution

The code includes no commissions, bid-ask spreads, expense ratios, or tracking error. In a thirty-holding basket containing thin funds such as KSA and BIZD, spreads and fund fees would reduce the reported Sharpe ratios.

One covariance estimate, no shrinkage

Every allocation rule uses the sample covariance matrix from 2,011 daily observations across 30 assets. It is invertible, but it is noisy. max_sharpe is especially sensitive to errors in the mean vector. The code uses no shrinkage estimator, factor model, or weight bootstrap.

A single fixed window

HISTORY_START and HISTORY_END are fixed. The code does not reselect, rebalance, or test other windows. These eight years include one pandemic crash and one bond bear market; another eight-year window would produce another basket.

No single command runs it

The selection modules have no main(). The notebooks are the only full path, so results depend on cell order and on constants that are not in a configuration file.
